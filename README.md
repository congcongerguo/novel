# 《注释》— 小说 + 短剧创作工程

> 一部**文学向生活流科幻**单元剧短篇集。一个 2026 年的程序员穿越到 2055 年——一个模型代理制、配额供给制的停滞世界，用"打破砂锅问到底"的精神在制度缝隙里讨生活，给荒诞世界写注释，也给自己的人生写注释。
>
> **根冲突（全书第一因）**：打破砂锅问到底 vs 只给答案的时代。
>
> **产品定位（2026-09-07 作者确认）**：终点是**抖音短剧**——**剧本做根，小说退为润色素材**。一集小说 = 一集短剧（M1 标准影视 + R1 短剧节奏），第一人称保留为陆远旁白。正文短篇集（1500-2500 字/集，密度优先）作为"故事素材库"继续存在，剧本见 `screenplay/`。

## 写作工作流

1. 开写一集前 → ① 读 `constitution.md` 红线；② 查 `season1-settings-inventory.md` 确认本集启用哪几条设定（≤3 样正面撞到）；③ 查 `novel-bible.md` 的**「主要矛盾 → 12 集小矛盾对照表」**，明确本集的小矛盾长自哪一面（A/B/D 表层 + C/E 深层）、家常落点是什么——防跑偏（别把小事写成"拯救世界"，也别写丢矛盾变流水账）
2. 起草 → 对齐 ep01（标杆样章）的节奏与文风
3. 写完 → **Tier 1 单集门禁**（`spec/review/review-process.md`）：三问表 + 五维评分 + 去 AI 感 + 台账更新 → 够格才定稿
4. 每完成一幕 / 整季 → **Tier 2 整体评审**：跨集通读七维，抓结尾同质化 / 主题句密度 / 意象复用等单集看不出的模式
5. 两层都过 → 才算完成

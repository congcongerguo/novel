## 二、角色一致性：KLEIN + 定妆照参考（关键）

### 为什么必须走参考图

旧流水线（`gen_ep01_frames_v2.py`）是**纯文生图**（`EmptyLatentImage` + `denoise=1.0`），角色只靠**文字模板**描述——所以模板里写错一个词（`slightly heavyset`），产出的 111 镜全偏胖。
**结论：角色一致性必须靠参考图，不靠文字描述。**

### 可用的节点（整合包自带，`sum_*` 系列）

| 节点 | 作用 | 关键输入/输出 |
|------|------|--------------|
| `sum_load_simple` | 载模型 + 采样参数 | out: `RUN_CONTEXT, MODEL, CLIP` |
| `sum_stack_flux2_Klein` | **拼提示词 + 最多 5 张参考图** | in: `context, model, ref_latent_img1..img5, imgN_strength, prompt` ／ out: `RUN_CONTEXT, CONDITIONING(pos), CONDITIONING(neg), STRING` |
| `sum_Ksampler` | 采样 | in: `context, seed, denoise, model, positive, negative` ／ out: `RUN_CONTEXT, IMAGE, RESAMPLE` |

### ✅ 跑通的接线（照抄即可）

```
sum_load_simple (unet=flux2_klein / clip=flux2 / vae=flux2-vae,
                 ckpt_name="None", clip2="None", lora="None",
                 width=832, height=1216, steps=24, cfg=1.0,
                 sampler=euler, scheduler=FlowMatchEulerDiscreteScheduler)
        ├─ RUN_CONTEXT ──────────────┐
        └─ MODEL ────────────┐       │
                             ↓       ↓
LoadImage(定妆照) ──IMAGE──→ sum_stack_flux2_Klein (img1_strength=0.65, prompt=…)
                                     ├─ CONDITIONING(pos) ─┐
                                     └─ CONDITIONING(neg) ─┤
                                                           ↓
                             sum_Ksampler (seed, denoise=1.0, model=sum_load_simple.MODEL,
                                           positive/negative 接上面两个 CONDITIONING)
                                     └─ IMAGE → SaveImage
```

### ⚠️ 三个坑（已踩过，别再犯）

1. **`ref_latent_img1` 名字骗人——它吃 `IMAGE`，不是 `LATENT`**
   直接接 `LoadImage` 的输出即可（接 VAEEncode 会报 `received_type(LATENT) mismatch input_type(IMAGE)`）
2. **`sum_load_simple` 必须显式把 `ckpt_name` / `clip2` / `lora` 设成 `"None"`**
   否则报 `ckpt_name and unet_name cannot be entered at the same time`
3. **`sum_Ksampler` 的 `model` 要接 `sum_load_simple` 的 MODEL 输出**
   `sum_stack_flux2_Klein` 的第 0 个输出是 RUN_CONTEXT，**不是** MODEL（接错会报 `received_type(RUN_CONTEXT) mismatch input_type(MODEL)`）

## 二·C、⚠️ Seedream 提示词铁律：**否定词会反噬**（2026-09-12 实测发现）

**Seedream 没有 negative prompt 机制** —— 你在提示词里写"不要冷""不要暗"，模型会把"冷""暗"当成画面内容执行。

**实测证据**（ep01 修图两轮）：

| 镜 | 第一轮写的（带否定词） | 结果 | 第二轮改成正向描述 | 结果 |
|----|----------------------|------|------------------|------|
| s07 | `冷白荧光…但必须保持暖色…**绝不能**偏冷偏蓝发灰` ＋ `no cool overall cast, no gray` | **−3.8 → −9.3**（越修越冷） | `明亮整洁…暖色照明…琥珀色调…温暖明亮` | **+37.2** ✅ |
| s24 | `周围是黑暗…**绝不过暗**` ＋ `not too dark` | 明度 **0.180 → 0.183** | `最亮的光源是手机屏幕…他很明亮，一眼就能看清` ＋ `well-exposed…clearly readable` | 明度 **0.217** ⬆ |
| s25 | `夜里黑下来…**绝不过暗**` ＋ `not too dark` | 明度 **0.180 → 0.164**（更暗） | `整条巷子被路灯光照得明亮温暖…清清楚楚` | 明度 **0.215** ⬆ |

### 铁律

1. **禁止在提示词里出现你想避免的概念**——不只禁"不要 X"，**连"X"这个字都别写**（哪怕在句中作否定）
   - ❌ `不要偏冷` / `not cold` / `no cool cast` / `绝不过暗` / `not too dark` / `avoid desaturation`
   - ✅ **改成正向、具体、可执行的画面描述**："整个空间浸在温暖的琥珀色调里""手机屏幕是画面里最亮的光源，把他的脸照得清清楚楚"
2. **要提亮就描述光源和可读性**（"最亮的光源是他手里的屏幕""五官清晰可见"），不要描述"别太暗"
3. **要提暖就描述光色**（"暖色顶灯""琥珀色调""暖橙色路灯光"），不要描述"别偏冷"
4. **改写否定句时，先想想这句话想让画面"是什么样"**——把"不是什么"翻译成"是什么"

> 这条同样适用于**角色描述**：写 `a lean man`，不要写 `not fat`。

### 参数基线

| 项 | 值 |
|----|-----|
| unet | `flux2_klein\F2K-9b-darkBeast_dbkBlitzV15_fp8.safetensors` |
| clip | `flux2_klein\qwen_3_8b_fp8mixed.safetensors`（`clip_type=flux2`） |
| vae | `flux2_klein\flux2-vae.safetensors` |
| 尺寸 | 832 × 1216（竖屏 9:16） |
| steps / cfg | 24 / 1.0（清洁配方下才加步数，见 spec-lock §4.1.1） |
| sampler / scheduler | `euler` / `FlowMatchEulerDiscreteScheduler` |
| **参考图强度 `img1_strength`** | **0.65 起点**（越高越像定妆照、越低越贴提示词；跨场景时可 0.5–0.75 之间调） |
| 首帧耗时 | 单张约 5–8 分钟（9B fp8，首次加载更久） |

### 参考图怎么给最好

- **定妆正面照**（`input/juese/<角色>/<角色>.png`）作 `ref_img1`：锁脸与体型
- **三视图 front**（`.../三视图/front.png`）可作 `ref_img2`：加服装与体型的稳定性
- 有多角色同框的镜（如 s18 s19 陆远+老头）：`ref_img1` = 陆远、`ref_img2` = 老头定妆（各带 strength）

### 上传参考图

ComfyUI 的 `LoadImage` 只认它自己 input 目录里的文件。用 `/upload/image` 上传（本项目脚本已实现：`.workbuddy/tmp/test_klein_ref.py` 的 `upload()`）。

## 二·B、付费通道：Seedream 5.0 Pro（火山方舟）· **角色一致性的最优解**

> 2026-09-11 实测跑通 ｜ 脚本 `.workbuddy/scripts/seedream_ref_gen.py`

### 为什么优先用它

| | 本地 KLEIN | **Seedream 5.0 Pro** |
|---|---|---|
| 参考图数量 | 5 张（`imgN_strength` 控强度） | **最多 10 张** |
| **坐标级编辑** | ✗ | ✅ **把 image 1 里的人放进 image 2 的场景**（1000×1000 归一化坐标） |
| 输出 | 832×1216 | **2K**（支持 9:16） |
| 单张耗时 | 5–8 分钟（4060 Ti 8G） | **87 秒**（实测） |
| 成本 | 免费 | 按张计费（含首张参考图免费额度） |

**决定性优势**：分镜首帧最需要的"把定妆照里的人放进新场景"，Seedream 是**原生能力**；KLEIN 只能靠 `img1_strength` 碰运气。

### ✅ 实测可用的调用方式

```python
payload = {
    "model": "doubao-seedream-5-0-pro-260628",
    "prompt": "用 image 1 中的人物……",        # 提示词里用 "image 1"/"image 2" 指代参考图
    "image": ["data:image/png;base64,...."],   # 单张传 str，多张传 list（≤10）
    "size": "2K",
    "output_format": "png",
    "watermark": False,
    "response_format": "url",
}
# POST https://ark.cn-beijing.volces.com/api/v3/images/generations
# Header: Authorization: Bearer $ARK_API_KEY   （key 在 ~/.workbuddy/.env）
```

**关键实测结论**：
1. **`image` 接受 base64 data URI**——不必先把参考图传到公网（省掉 OSS/COS 上传步骤）
2. 耗时 **87 秒/张**；返回 URL **24 小时有效**，脚本已即时下载落地
3. 坐标系（要做"精确摆位"时用）：**1000×1000 归一化**，写法如
   `Place the subject from image 1 179 283 796 986 into image 2 118 331 933 871`
4. 参考图限制：单张 ≤30MB、总像素 ≤6000×6000、宽高 >14px

### 分工建议（成本 vs 质量）

| 走哪条 | 用在哪些镜 |
|--------|-----------|
| **Seedream（付费）** | **锚点图全部 6 张** + 所有**含角色正脸/多角色同框**的镜（s01 s02 s04 s05 s17 s18 s19 s22 s24）+ 集尾 s24 手机 2% |
| **本地 KLEIN（免费）** | 空镜、道具特写、场景建立（s03 s06 s13 s14 s15 s16 s23 s25）等对角色脸要求不高的镜 |

> 一句话：**脸贵的走付费，景便宜的走本地。**

## 四、竖屏铁律（沿用 shotlist v2 的结论）

1. 禁用 `wide shot / panoramic / widescreen / horizontal`
2. 用 `vertical 9:16 composition`、`vertical framing`
3. 空间纵深改为**竖向堆叠**（队伍向画面深处延伸、建筑在上、人在下）
4. 负向词必带：`letterbox, black bars, widescreen crop, horizontal panorama`

## 一、提示词的七个固定段落（缺一段都不行）

```
subject_definitions:
<Subject 1> is ... defined by <Picture 2> (character sheet) and <Picture 3> (full-body front view): ...
<Subject 2> is ... in <Picture 1>: ...
<Picture 1> is the first frame of [Shot 1]: ...

summary:
[keyframe completion + reference generation] The target video starts from <Picture 1> as its exact first frame: ... <Picture 2> and <Picture 3> define <Subject 1>'s identity and clothing only.

retention_analysis:
<Subject 1> (appears in [Shot 1]): fully_preserved | partially_preserved - ...
<Subject 2> (appears in [Shot 1]): fully_preserved - ... exactly as in <Picture 1>.
<Picture 1> ([Shot 1] first frame): fully_preserved - the video opens on this exact frame.

detailed_description:
The target video is a photorealistic documentary-style vertical 9:16 shot with ...; [机位/轴线/光色].
[Shot 1] The shot begins from <Picture 1>: ... From 00:00.5 to 00:02.0, ... From ... No other dialogue.

overall_soundscape: ...

non_diegetic_music: N/A
```

标签含义：`<Picture 1>` = 本镜首帧（图生视频的起始帧）；`<Picture 2>` = 角色定妆卡；`<Picture 3>` = 角色全身正面。传给节点 `ref_images` 的顺序必须与之**一一对应**。

## 二、三条铁律（2026-09-12 三个事故 ← 就是这三条）

### 铁律 1 · 场景/道具**必须**锚定 `<Picture 1>`
```
✅ <Subject 2> is the dawn alley in <Picture 1>: a narrow old-town alley with ...
❌ <Subject 2> is the dawn alley: a narrow old-town alley with ...        ← 视频会与首帧脱钩
```
**判断法**：每个"场景/道具类"的 `<Subject N>`，句子里必须出现 `in <Picture 1>`。

### 铁律 2 · 对白**必须**用 `<d>[Chinese] 台词。</d>`，并标说话人
```
✅ From 00:00.5 to 00:02.0, <Subject 1> (S1) says flatly, <d>[Chinese] 你还在这儿？</d>
❌ From 00:00.5 to 00:02.0, she answers him.          ← 模型没有语言约束 → 输出英文或乱码
❌ 有对白的镜写 "No dialogue."                        ← 模型自己编语音
```
- 说话人标 `(S1)` / `(S2)`，与 `<Subject 1>` / `<Subject 2>` 对应
- 每句 `<d>` 前面要有"谁、用什么语气"（`says flatly` / `answers without lifting her head`）—— 这句决定语气
- 段落收尾：有对白写 `No other dialogue.`；无对白写 `No dialogue.`

### 铁律 3 · 声景里**禁止**出现"说话类"词（除非该镜确实有 `<d>` 对白）
```
❌ overall_soundscape: ...; her voice carrying on the air, footsteps receding     ← 触发无约束语音
✅ overall_soundscape: Street bed of footsteps and distant carts; the soft scuff of a cloth bag
```
禁用词（无对白镜）：`voice / voices / says / speaking / talking / murmur / whisper / words`
无对白镜的声景只能写**物理声**：脚步、风、电流嗡声、金属摩擦、布料、门帘、远处车流、呼吸。

### 铁律 4 · **空镜/道具首帧上，禁止写人物出场或人物动作**（2026-09-12 事故）

`图生视频`模式里首帧是**几何锚点**：画面里**已有**的东西会被严格保留，画面里**没有**的东西由模型即兴生成。

> 所以 —— **首帧里没有人物，就不要在提示词里写人物。**

```
❌ s13（首帧 = A1 废品收购站空镜）：
   subjects: <Subject 1> is the lean man …; seen small, walking into frame.
   beats:    00:02.6–00:04.6 他从左边走进画面、停下看着那堆东西
             00:04.6–00:05.9 他蹲下、坐下、背靠着墙
   → 后果：H3 凭空"造"了一个陆远 —— 空镜首帧里没有任何东西可以锚定他的
     外观，角色卡只是软参考。于是：
     ① 这个"陆远"跟下一个镜头的陆远对不上 → 观众看到"**像变了个人**"
     ② 它把 s14 的动作（坐下）提前演完了 → 两镜**动作重复**
     ③ 与首帧源图的相关度从 0.993 掉到 **0.506**（实测）
```

✅ 正确写法：空镜只写**环境自身的微动**
```
beats: 灰尘在光柱里浮动、又落下 / 棚布被风吹起一次又落回 / 一块裸金属边缘吃光、又失去光
close: No dialogue.
```

**判定法（每镜出片前必过）**：问一句 —— **该镜的首帧里，有没有那个人 / 那件东西？**
- 首帧里**有** → 可以写它动
- 首帧里**没有** → **一个字都别写它**，否则模型会造一个不可控的出来

**本片同类核查结果**：`s13`（空镜 + 人物动作，**已修正为纯空镜 124 帧**）／`s01`（手部特写，画面无人脸，可接受）／`s15`（手部刮锈，无脸，可接受）／`s24`（首帧本身已含半张脸，可接受）。

## 三、机位与轴线：**同场戏共用常量**

同一场景的连续对白镜，机位与朝向必须写死且一致，否则观众会看到人物"一会儿背对屏幕、一会儿又转过来看镜头"。

在 `tools/gen_ep01_h3.py` 里已抽成常量（改一处，全场景生效）：

| 常量 | 用于 | 要点 |
|------|------|------|
| `AXIS_ROOM` / `AXIS_ROOM_WIDE` | s01–s02 废弃屋 | 低机位手持；插座与手在窄画幅里纵向叠放 |
| `AXIS_STREET` | s03 街头 | 他在画面下三分之二；街头与店面向上叠；机位不离开他的位置 |
| `AXIS_STALL` | s05 摊位 | 两人在下三分之二**面对面四分之三侧**，谁都不看镜头 |
| `AXIS_QUEUE` | s06 队列 | 队列自下而上纵向排入建筑；机位锁死在他这一段 |
| `AXIS_WINDOW` ⭐ | **s07–s11 配给点** | **侧后 3/4、面向画面右侧的屏幕、绝不算转向镜头**（必须与首帧一致） |
| `AXIS_JUNK` | s13–s20 废品站 | 塑料棚布在画面上部切天；锈机在下半部；手持在他眼高 |
| `AXIS_DUSK` | s21 黄昏 | 两人在同一水平蹲着、面对面四分之三侧 |
| `AXIS_NIGHT` | s22–s25 夜 | 钠灯暖橙照亮整条巷；暗部暖褐不死黑 |

**通则**：连续对白镜只有两种合法朝向 —— ① 面对画外对象（观众看侧后）② 两人面对面（观众在两人之间/一侧）。**禁止同场混用"侧后"与"正面朝镜头"。**

## 四、旁白（V.O.）策略：**不进 H3**

V.O. 要的是"心里的话"（不张嘴、音色可控），H3 做不到这两点，还会抢占对白音轨。

> **规则：6 句 V.O. 一律后期单独配音**；对应镜写 `No dialogue.`，且描述里不出现任何"说话"动作。

## 五、⚠️⚠️ 选节点：**首帧锁定 vs 参考图，是不可兼得的两个模式**

这一条是 2026-09-12 挖出来的**最深一层根因**，比提示词写法更要紧。

`MiniMaxH3ReferenceToVideo`（原管线用的节点）**输入里根本没有 `first_frame`**，只有 `ref_images`。
模型文件是 `minimax_h3_**ref2va**` = reference-to-video+audio——**参考图只是"身份/风格参考"，不承担首帧几何锚点**。

> 所以提示词里写 `The target video starts from <Picture 1> as its exact first frame` 是**一厢情愿**：**节点层面就没有这个能力。**

**像素级实测证据**（`tools/frame_fidelity.py`，抽视频第 0 帧与首帧源图比对）：

| 素材 | 第0帧 vs 首帧源图 相关度 |
|------|----------------------|
| 新 ep01 v2.0（官方语法版） | 0.13 / 0.15 / 0.43 |
| 旧 ep01 v1（错误版 25 镜均值） | ≈0.20 |
| **旧 ep02「被认为是跑通的」16 镜均值** | **0.090** |

**结论：从来没有锁住过首帧**——连此前那批也一样。（指标已校准：同视频相邻帧 corr 0.80；不同镜 corr −0.11；源图对自身 1.00。）

**H3 节点全景**：

| 节点 | `first_frame` | 音频 | `ref_images` |
|------|:---:|:---:|:---:|
| `MiniMaxH3ReferenceToVideo`（原用） | ❌ | ✅ | ✅ |
| `MiniMaxH3ImageToVideo` | ✅ | ❌（疑无音频输出） | ❌ |
| **`Yuan_MiniMaxH3Video`** | ✅ | ✅（`audio_vae`） | ✅ `ref_image_1..9` |
| `RHMiniMaxH3FL2VA*` 系列 | ✅ first/last | ✅ | — |

**`Yuan_MiniMaxH3Video` 的 `mode` 二选一（互斥）**：
- **`图生视频`** → `first_frame` / `last_frame` 作**几何锚点**（tooltip 明写"作为几何锚点"）→ **首帧会被锁死**
- **`参考图生视频`** → `<Picture i>` 参考（= `MiniMaxH3ReferenceToVideo` 的行为）→ 首帧不锁

**取舍与我们的选择**：首帧本来就是用定妆照 + Seedream 生成的，**脸已经是对的**，所以
**优先用 `图生视频` 模式锁死首帧**，角色一致性交给首帧承载。

> 验证脚本：`tools/test_h3_modes.py`（同一镜跑 `i2v` / `i2v_ref` / `ref` 三配置做 A/B）
> **待确认**：`图生视频` 模式下是否仍有音频轨（能否继续用 `<d>[Chinese]` 出中文对白）。若无音频，则对白全部转后期配音。

## 六、时间轴写法

```
✅ From 00:00.5 to 00:02.0, ...     ← 起止都有
❌ From 00:00.5, ...                ← 只有起点，时序不精确
```
- 时间点对齐帧数：`frames / 24 = 时长`（如 175 帧 = 7.29 秒，最后一段不要超过 07.2）
- 台词时长按中文口语 **5 字/秒**估算；系统播报可到 6 字/秒
- 一镜对白总量超过镜头时长 → **分配台词而不是砍镜头**（可跨镜延续）

## 七、参数与工程铁律

| 项 | 值 |
|----|----|
| 分辨率 | 480×832（竖屏 9:16） |
| 帧数 | `124 + 17k`（k=0..10 → 124/141/158/175/192/209/226/243/260/277/294） |
| 步数 / 采样器 / 调度 | 25 / `res_multistep` / `simple`，denoise 1.0 |
| `ref_image_size` | `match`（`Yuan_MiniMaxH3Video` 里显示为 `匹配`） |
| 输出 | 24fps，`VAEDecodeAudio` + `CreateVideo(audio=…)` → 带音频轨 |
| 模型文件 | `minimax\minimax_h3_ref2va_pruned_int8_convrot.safetensors`（ref2va 权重两个模式共用） |

**两条踩过的坑**：
1. **必须串行跑** —— 并行两批抢同一 GPU，单镜耗时从 6–7 分钟暴涨到 11–38 分钟
2. **Windows TIME_WAIT 端口耗尽** —— 每 10 秒轮询用 `urllib` 新建连接，一镜 40–80 次 → 端口耗尽 → 提交/下载被掐断。**用 `requests.Session` 连接池 + `urllib3.Retry`，轮询 15s**

**产物取回**：视频已生成但脚本中断时，从 `/history/<pid>` 取 `outputs` 里的 `filename/subfolder`，用 `/view?filename=…&subfolder=…&type=output` 下载 —— **不要重跑**。

**ffmpeg 不在 PATH**：用 `C:/Users/oo/anaconda3/envs/indextts/Library/bin/ffmpeg.exe`
